Data

This run used a synthetic ICU cohort generated by src/cohort.py. It is not patient data and carries no clinical meaning. Events are driven by a latent process the model cannot fully observe, so achievable performance is bounded well below 1.0 by construction — a synthetic cohort a model scores 0.99 on would teach you nothing. MIMIC-IV and eICU are credentialed and are not bundled here.

The question the label encodes

Not "is this patient deteriorating now" — a monitor answers that and needs no model. The label here is will this patient deteriorate in the next four hours, and rows where the event has already started are dropped, because predicting an event in progress is not early warning.

Splitting is by patient, never by observation. Two windows from one patient share a baseline and a latent trajectory, so a random row split leaks the patient across train and test and inflates every number on this page. That single choice moves results more than any model change here.

Calibration is where the model wins

Expected calibration error, lower is better. The ward alarm's score is not a probability at all — it is a normalised vital — so its ECE of 0.218 is expected. The point is the gap: after isotonic calibration the model's stated risk is within 0.010 of the observed frequency, which is what makes a number like "18% risk in the next four hours" safe to put in front of a clinician.

Why matched sensitivity

Both systems are set to the same 80% sensitivity before their false alerts are counted. Comparing alarm burden at different sensitivities is the most common way to make an alerting result look better than it is: any system can cut false alerts by catching fewer events.

The reduction here is 6.2% on synthetic data. That is the honest analogue of a false-alarm-reduction claim, and it is a good deal smaller than the figures usually quoted for this kind of system.

Does the uncertainty estimate earn its place?

A negative result

The chart shows AUROC when the model defers its least-certain cases to a human. A useful uncertainty estimate would make AUROC rise as uncertain cases are removed. It falls — from 0.680 keeping everything to 0.533 keeping only the most confident half.

The ensemble spread is not identifying cases the model gets wrong. It is identifying cases with low predicted probability, where members agree because the answer is easy and the event rate is low. Brier improves across the same sweep for exactly that reason, which is why Brier alone would have hidden this.

So the uncertainty estimate is reported and is not recommended for triage in its current form. Conformal prediction, which gives coverage guarantees rather than a spread, is the obvious next thing to try.

Reproduce it

cd icu-early-warning
pip install -r requirements.txt
python -m pytest tests/ -q
python -m src.demo

To run it on MIMIC-IV or eICU, replace src/cohort.py with a loader returning the same Patient shape. Nothing else changes.

What this does not establish

  • The cohort is synthetic. Every number here describes a generator, not a hospital, and none of it transfers to MIMIC-IV or eICU without being re-run.
  • AUROC near 0.70 is what this generator permits, because events are driven by a latent the features only partly observe. It is neither a good nor a bad clinical result — it is not a clinical result at all.
  • No external validation, no prospective evaluation, no site transfer.
  • Alert fatigue is modelled as a count of false alerts. Real alarm burden depends on timing, clustering and who is in the room.
  • The uncertainty estimate does not support selective prediction here, as shown above. It should not be used for triage.
